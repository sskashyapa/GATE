🛑 Module 5: Deadlocks

Coffman Conditions, Banker's Algorithm, and Resource Allocation Graphs (RAG)

1️⃣ What is a Deadlock?

A situation where a set of processes are blocked because each process is holding a resource and waiting for another resource held by some other process in the set.

The 4 Necessary Conditions (Coffman Conditions)

Deadlock ONLY happens if ALL FOUR of these conditions occur simultaneously:

1. Mutual Exclusion

At least one resource must be held in a non-shareable mode (only one process can use it at a time).

2. Hold and Wait

A process must be holding at least one resource and waiting to acquire additional resources held by other processes.

3. No Preemption

Resources cannot be forcibly taken away from a process; they must be released voluntarily.

4. Circular Wait

A closed chain of processes exists, where P1 waits for P2, P2 waits for P3... and Pn waits for P1.

2️⃣ Deadlock Handling Strategies

  • Deadlock Ignorance (Ostrich Algorithm): Just ignore it! Pretend deadlocks never happen. This is exactly what Windows and Linux do because deadlocks are rare and handling them is too expensive.
  • Deadlock Prevention: Design the system so that at least ONE of the 4 Coffman conditions is strictly logically impossible (e.g., denying Circular Wait by forcing processes to request resources in strict numerical order).
  • Deadlock Avoidance: OS checks every resource request. If granting it leads to an "unsafe state", it makes the process wait. (Banker's Algorithm).
  • Deadlock Detection & Recovery: Let the deadlock happen, detect it using algorithms, and recover by killing processes or rolling them back.

3️⃣ Banker's Algorithm (Deadlock Avoidance)

This is the single most tested numerical topic in GATE Deadlocks. The algorithm checks if there is a Safe Sequence in which all processes can finish without getting stuck.

The Golden Rule of Banker's Algorithm:

Need = Max - Allocation

If Need <= Available, the process executes, finishes, and releases ALL its allocated resources back to Available (Available = Available + Allocation).

⚠️ GATE TRAP: Unsafe State vs Deadlock

If the system is in a Safe State, deadlock is 100% impossible.
However, if the system is in an Unsafe State, it DOES NOT mean it is deadlocked! It only means deadlock is possible if processes request their maximum resources.

4️⃣ Resource Allocation Graph (RAG)

A visual way to check for deadlocks. Vertices are Processes (Circles) and Resources (Rectangles).

Single Instance Resources

If every resource has exactly 1 instance:
Cycle = Deadlock. (100% guaranteed).

Multiple Instance Resources

If resources have >1 instance:
Cycle ≠ Deadlock necessarily!
(It's only a necessary condition, you must run Banker's algorithm or reduction to be sure).
