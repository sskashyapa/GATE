🗂️ Module 8: File Systems

Allocation Methods, UNIX Inode Architecture, and Max File Size Math

📖 Core Fundamental Theory: The "Why"

Hard drives are massive, continuous strips of magnetic or solid-state storage. Just like RAM is divided into "Frames", the hard disk is divided into fixed-size hardware blocks (usually 4KB). The Operating System's job is to figure out how to map a user's File to these physical disk blocks.

The Directory Structure

A directory is simply a special type of file that contains a list of other files. The OS uses it to map a human-readable file name (like resume.pdf) to a specific starting block on the hard drive.

2️⃣ File Allocation Methods

How does the OS distribute the blocks of a file across the hard drive? There are 3 main strategies:

1. Contiguous Allocation

Every file occupies a set of contiguous blocks on the disk.

  • Pros: Extremely fast (minimal disk head movement), supports Direct Access.
  • Cons: Suffers from massive External Fragmentation. Files cannot grow easily.

2. Linked Allocation

Each file is a linked list of disk blocks. Each block contains a pointer to the next block. (Used in Windows FAT32).

  • Pros: No external fragmentation. Files can grow infinitely.
  • Cons: Only supports Sequential Access (to read block 10, you must read blocks 1-9). Pointers waste disk space.

3. Indexed Allocation

Brings all the pointers together into one specific block called the Index Block. Each file has its own index block.

  • Pros: Supports Direct Access without external fragmentation.
  • Cons: Suffers from pointer overhead (wastes an entire block just for pointers, even for tiny files).

3️⃣ The UNIX Inode (Indexed Allocation on Steroids)

To solve the issue of massive files needing huge index blocks, UNIX created the Inode (Index Node). An inode contains the file's metadata and a mix of direct and indirect pointers. This is the source of all GATE numericals for this chapter.

The Standard Inode Structure:

  • 🟢 Direct Pointers: Point directly to the disk blocks containing the file's data. (Usually 12 of these).
  • 🟡 Single Indirect Pointer: Points to an index block, which contains pointers to data blocks.
  • 🟠 Double Indirect Pointer: Points to a block containing pointers to index blocks, which then point to data blocks.
  • 🔴 Triple Indirect Pointer: (You get the idea... 3 levels deep).

The Ultimate "Max File Size" Formula

Let B = Block Size (e.g., 4KB), and P = Pointer Size (e.g., 4 Bytes).
The number of pointers that can fit inside one index block is: N = B / P.

Max File Size = [ D + (N) + (N2) + (N3) ] × B

Where D is the number of Direct Pointers.

⚠️ GATE TRAP: The Block vs Bytes confusion

When doing the calculation N = B / P, make sure both are in Bytes! If Block Size is 4KB and Pointer size is 4B, then N = (4 × 1024) / 4 = 1024 pointers.
Also, remember the final answer will be in Bytes. GATE often asks for the answer in GB or TB, so divide by 1024 accordingly!
