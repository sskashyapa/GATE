1️⃣ What is an Operating System?

Definition, purpose, and the big picture

Definition: An Operating System (OS) is a system software that acts as an intermediary between the user and the computer hardware. It manages hardware resources and provides services to application programs.

🏗️ Where does the OS sit?

🎯 Two Key Roles of an OS

1. Resource Manager

Manages CPU time, memory, disk space, and I/O devices. Decides who gets what, when, and for how long.

2. Extended Machine (Abstraction)

Hides ugly hardware details. Instead of writing disk controller commands, you just call open("file.txt").

📋 What does an OS do?

✓ Process Management

✓ I/O Device Management
✓ Security & Protection
✓ Networking

🎓 Exam Tip

Q: "Is the OS hardware or software?" → It is system software. It's the first program loaded into memory when the computer starts (bootstrapping).

2️⃣ Evolution of Operating Systems

How OS evolved over decades — each generation solved a problem

🔧 Gen 0: No OS (1940s–50s)

Programs entered via switches and punch cards. One job at a time. The programmer was the OS.

📦 Batch Systems (1950s–60s)

Jobs collected in batches and executed sequentially by a resident monitor. No user interaction during execution.

❌ Problem: CPU sits idle during I/O operations (very slow)

🔀 Multiprogramming (1960s)

Multiple jobs loaded in memory. When one job does I/O, the CPU switches to another job. CPU never idle!

✅ Solution: Maximized CPU utilization

❌ Problem: No user interaction, no fairness guarantee

⏱️ Time-Sharing / Multitasking (1970s)

CPU time divided into small time slices (quantum). Each user gets a turn, creating the illusion of simultaneous execution. E.g., UNIX.

✅ Solution: Interactive computing, multiple users at once

⚡ Real-Time OS (RTOS)

Guarantees response within a strict deadline. Used in missiles, medical devices, robotics.

🔵 Hard RTOS: Missing deadline = system failure 🟡 Soft RTOS: Deadline miss = degraded quality

☁️ Modern OS (Today)

Distributed systems, cloud OS, mobile OS, containerized environments.

🔑 Key Difference to Remember

Multiprogramming Multiple jobs in memory, CPU switches on I/O wait. No time quantum.
Multitasking Same as multiprogramming + time slicing (preemptive switching).
Multiprocessing Multiple CPUs/cores running processes in parallel.

3️⃣ Types of Operating Systems

Different OS types for different needs

🖥️ Desktop OS

Single user, rich GUI. Focus on responsiveness.

Ex: Windows, macOS, Ubuntu Desktop

🏢 Server OS

Multi-user, high throughput, network services.

Ex: Windows Server, RHEL, Ubuntu Server

📱 Mobile OS

Touch input, power-efficient, app sandboxing.

Ex: Android, iOS

🔌 Embedded OS

Runs on dedicated hardware with limited resources.

Ex: Washing machines, ATMs, routers

⏱️ Real-Time OS

Strict timing guarantees. Deterministic scheduling.

Ex: VxWorks, FreeRTOS, QNX

☁️ Distributed OS

Multiple machines appear as one system.

Ex: Amoeba, Google's internal systems

4️⃣ OS Structure / Architecture

How the kernel itself is organized internally

▶ 🏛️ Monolithic Kernel — Everything in one big block

All OS services (file system, device drivers, memory management, scheduling) run in kernel space as a single large process.

Examples: Linux, traditional UNIX

▶ 🔬 Microkernel — Minimal kernel, services in user space

Only essential services (IPC, basic scheduling, memory management) in kernel. Everything else (file system, drivers) runs as user-space servers.

▶ 🔄 Hybrid Kernel — Best of both worlds

Microkernel design philosophy but runs some user-space services in kernel space for performance.

✅ Balances speed and modularity

▶ ⚗️ Exokernel — Minimal abstraction, max control

Kernel only handles resource protection (who owns what). Applications manage their own abstractions via library OS. Research concept.

✅ Maximum flexibility for applications ❌ Very complex to program

Examples: MIT Exokernel (research)

5️⃣ System Calls

The programmatic interface between user programs and the OS kernel

Definition: A system call is a request made by a user program to the OS kernel to perform a privileged operation (like reading a file, creating a process, or allocating memory).

⚙️ How a System Call Works

📂 Categories of System Calls

Category Examples Purpose
Process Control fork(), exec(), exit(), wait() Create, terminate, and manage processes
File Management open(), read(), write(), close() Create, delete, read, write files
Device Management ioctl(), read(), write() Request/release devices, I/O operations

Communication pipe(), shmget(), socket() IPC — message passing, shared memory

💻 Real Example: Creating a child process in C

#include <stdio.h>
#include <unistd.h>

int main() {
    int pid = fork();  // System call! Creates child process

    if (pid == 0) {
        printf("I am the child! PID=%d\n", getpid());
    } else {
        printf("I am the parent! Child PID=%d\n", pid);
    }
    return 0;
}

Here fork() and getpid() are system calls. printf() is a library function that internally uses the write() system call.

6️⃣ User Mode vs Kernel Mode

Dual-mode operation — the foundation of OS protection

Why two modes? To protect the OS from buggy or malicious user programs. If any program could directly access hardware, one bad program could crash the entire system.

👤 User Mode (Mode bit = 1)

  • • Application programs run here
  • • Restricted access — cannot directly access hardware or memory of other processes
  • • Attempting a privileged instruction → Trap (exception)
  • • Must use system calls for OS services

⚙️ Kernel Mode (Mode bit = 0)

  • • OS kernel runs here
  • • Full access — can execute any instruction, access all memory & hardware
  • • Can execute privileged instructions (disable interrupts, modify page tables, I/O)
  • • Entered via system call, interrupt, or exception

🎓 Exam Tip

The mode bit is a hardware bit in the CPU's status register. It's set by hardware — user programs cannot change it directly. Only a trap (system call) or interrupt can switch from user → kernel mode.

7️⃣ Interrupts & Interrupt Handling

How the CPU knows something needs attention

Definition: An interrupt is a signal to the CPU that an event has occurred and needs immediate attention. The CPU pauses current execution, handles the interrupt, then resumes.

📋 Types of Interrupts

⚡ Hardware Interrupts (External)

Generated by hardware devices to signal events.

  • • Keyboard key pressed
  • • Mouse moved / clicked
  • • Disk I/O completed
  • • Timer interrupt (clock tick)
  • • Network packet arrived

🖥️ Software Interrupts (Internal)

Generated by programs intentionally or by errors.

  • • Trap — System call (intentional)
  • • Exception — Division by zero
  • • Fault — Page fault (recoverable)
  • • Abort — Hardware failure (unrecoverable)

🔄 Interrupt Handling Steps

1

Interrupt occurs — device sends signal on the interrupt line

2

CPU saves state — pushes PC (program counter), registers onto stack

3

CPU looks up ISR — uses the Interrupt Vector Table (IVT) to find the address of the Interrupt Service Routine

4

ISR executes — handles the event (e.g., reads keyboard buffer)

5

State restored — CPU pops saved registers, resumes interrupted process

🔑 Interrupt Vector Table (IVT)

A table stored in memory that maps each interrupt number → address of its handler (ISR). Like a phone directory: "interrupt 14 → call the page fault handler".

🎓 Key Points for Exams

  • • Interrupts are the basis of modern OS design — without them, the CPU would have to constantly poll devices (wasteful)
  • • Timer interrupt is what makes preemptive multitasking possible — it fires periodically to give the OS a chance to switch processes
  • • Trap ≠ Interrupt: A trap is synchronous (caused by the program), an interrupt is asynchronous (caused by external device)

🧪 Practice Questions — Test Yourself!

▶ Q1: What is the key difference between multiprogramming and time-sharing?
Answer: Both keep multiple jobs in memory. Multiprogramming switches the CPU to another job only when the current job does I/O (non-preemptive). Time-sharing forcefully switches using a timer interrupt after a fixed time quantum (preemptive), ensuring interactive response for all users.
▶ Q2: Why can't a user program directly execute a privileged instruction like disabling interrupts?
Answer: Because the CPU runs user programs in User Mode (mode bit = 1). Privileged instructions can only execute in Kernel Mode (mode bit = 0). If a user program tries, the CPU generates a trap (exception), and the OS typically terminates the offending process.
▶ Q3: In a microkernel OS, how do the file system and device drivers communicate?
Answer: Through Inter-Process Communication (IPC) via message passing through the microkernel. Since both run as user-space servers, they can't call each other directly. This adds overhead but improves reliability — if the file system crashes, the kernel and other services keep running.
▶ Q4: What happens when you call printf("Hello") in C?
Answer: printf() is a library function (not a system call). Internally, it formats the string, then invokes the write() system call to send the data to stdout (file descriptor 1). The write() call traps into the kernel, which handles the actual I/O to the screen.
▶ Q5: Why is the timer interrupt critical for an OS?
Answer: The timer interrupt fires at regular intervals, giving control back to the OS. Without it, a user process could run forever and never return control to the OS (infinite loop). It enables: (1) Preemptive scheduling — OS can switch processes, (2) Time-sharing — fair CPU distribution, (3) OS keeps running — prevents system hangs.

• OS = Resource Manager + Abstraction Layer
• Evolution: Batch → Multiprogramming → Time-sharing
