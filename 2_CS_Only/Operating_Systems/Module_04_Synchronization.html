🔒 Module 4: Process Synchronization

Critical Sections, Mutex, Semaphores, and Peterson's Solution

1️⃣ The Critical Section Problem

When multiple processes share data (like a shared variable or database), concurrent access can lead to data inconsistency (Race Condition). The segment of code where this shared memory is accessed is called the Critical Section (CS).

1. Mutual Exclusion (Mandatory)

If Process P1 is executing in its CS, NO other process can be executing in their CS.

2. Progress (Mandatory)

If no one is in the CS, and some process wants to enter, it cannot be postponed indefinitely by processes not interested in entering.

3. Bounded Waiting (Optional)

There must be a limit on how many times other processes can bypass a waiting process to enter the CS.

2️⃣ Semaphores (The Core of GATE OS)

A Semaphore (S) is an integer variable used to solve the critical section problem. It can only be accessed via two standard atomic operations: wait() and signal().

wait(S) / P(S) / down(S)

wait(S) { while (S <= 0) ; // busy wait (or block) S--; }

signal(S) / V(S) / up(S)

signal(S) { S++; }

Types of Semaphores:

  • Binary Semaphore (Mutex): Value is 0 or 1. Used strictly for Mutual Exclusion.
  • Counting Semaphore: Value can range over an unrestricted domain. Used to control access to a resource with multiple instances (e.g., 5 printers).

⚠️ GATE TRAP: The Negative Semaphore Trick

In a counting semaphore implementation that uses a blocking queue instead of busy waiting, a negative semaphore value (-N) means exactly N processes are blocked in the waiting queue! If S = -4, four processes are stuck waiting.

3️⃣ Peterson's Solution

A classic software-based solution for 2 processes. It uses two variables: int turn; and boolean flag[2];

Process 0 (P0)

flag[0] = true; turn = 1; while (flag[1] && turn == 1); // wait // CRITICAL SECTION flag[0] = false; // exit

Process 1 (P1)

flag[1] = true; turn = 0; while (flag[0] && turn == 0); // wait // CRITICAL SECTION flag[1] = false; // exit

Note: Peterson's solution guarantees Mutual Exclusion, Progress, and Bounded Waiting. However, it only works for exactly 2 processes.
