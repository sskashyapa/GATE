🧮 Module 7: Virtual Memory & Numericals

Paging Math, TLB Access Time, and Page Replacement Algorithms

1️⃣ The Core Paging Math

Every GATE paging numerical starts by breaking down the memory sizes into powers of 2. Memorize these mappings:

Logical Address Space (LAS)

  • LAS Size: e.g., 4 GB = 232 Bytes
  • Logical Address (LA): Log2 (LAS) = 32 bits
  • LA is split into: Page Number (p) + Offset (d)

Physical Address Space (PAS)

  • PAS Size: e.g., 16 GB = 234 Bytes
  • Physical Address (PA): Log2 (PAS) = 34 bits
  • PA is split into: Frame Number (f) + Offset (d)

Crucial Formulas to Memorize:

Offset bits (d) = Log2 (Page Size)

Number of Pages = LAS / Page Size = 2p

Number of Frames = PAS / Page Size = 2f

Page Table Size = Number of Pages × PTE Size

2️⃣ Translation Lookaside Buffer (TLB)

Because the Page Table is stored in RAM, translating an address and fetching the data requires TWO memory accesses (one for the table, one for the data). This is very slow! To fix this, we use a TLB (a small, extremely fast hardware cache) inside the MMU.

Effective Access Time (EAT) Formula:

Let H = TLB Hit Ratio, C = TLB Access Time, M = Main Memory Access Time.

EAT = H × (C + M) + (1 - H) × (C + 2M)

Explanation: If TLB Hit, we access TLB (C) then RAM (M). If TLB Miss, we access TLB (C), then RAM for Page Table (M), then RAM for Data (M).

3️⃣ Page Replacement Algorithms

When a CPU requests a page that is NOT in RAM, a Page Fault occurs. The OS must bring the page from the hard drive. If the RAM is full, the OS must evict an old page. How does it choose?

1. First-In, First-Out (FIFO)

Evicts the oldest page in memory. Simple to implement using a queue, but suffers from terrible performance.

⚠️ GATE Favorite: Belady's Anomaly

Only FIFO suffers from this! Belady's Anomaly is a situation where giving the process more physical memory frames actually increases the number of page faults.

2. Least Recently Used (LRU)

Evicts the page that has not been used for the longest time. Highly effective and widely used in real OS. Does NOT suffer from Belady's anomaly.

3. Optimal Page Replacement (OPT)

Evicts the page that will not be used for the longest period of time in the future. It guarantees the absolute minimum number of page faults, but it is impossible to implement practically because the OS cannot see the future.

4️⃣ Thrashing (Concept)

If a process does not have enough frames to hold its actively used pages (its Working Set), it will constantly trigger Page Faults.

The CPU becomes idle because it's always waiting for the disk. The OS sees the CPU is idle, so it loads more processes into RAM, making the frame shortage even worse!

Thrashing Definition: A state where the system is spending more time swapping pages in and out of the hard drive than executing actual CPU instructions. CPU utilization drops to near zero.
