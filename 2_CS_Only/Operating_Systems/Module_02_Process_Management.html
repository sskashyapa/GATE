Process Management — Fundamentals

The life cycle of programs in execution

1️⃣ Program vs. Process

📄 Program

  • • Static Entity: Just a file residing on disk (e.g., chrome.exe, script.py).
  • • Takes up disk space, not RAM.
  • • Passive state of instructions.

⚙️ Process

  • • Dynamic Entity: A program in execution.
  • • Resides in Main Memory (RAM).
  • • Active: Needs CPU, memory, and resources to run.
  • • *One program can have multiple processes* (e.g., opening 5 Chrome tabs).

Process Memory Layout: When a process is loaded into RAM, it consists of 4 main sections:

  • Text Section: Compiled code/instructions.
  • Data Section: Global and static variables.
  • Heap: Dynamically allocated memory during runtime (e.g., malloc() or new). Grows upward.
  • Stack: Temporary data like function parameters, return addresses, and local variables. Grows downward.

🎓 GATE Important Facts:

  • Multiprogramming Degree: Determined by the number of processes in the READY state + RUNNING state.
  • Suspended States: Sometimes OS swaps out processes to disk due to low RAM. This creates two extra states: Suspend-Ready and Suspend-Wait.
  • On a single-core CPU, only ONE process can be in the RUNNING state at any exact microsecond.

3️⃣ Process Control Block (PCB)

The OS's data structure to keep track of a process. Also called Task Control Block.

Program Counter (PC): Points to the next instruction to be executed for this specific process. Vital for resuming execution after an interrupt.

CPU Registers: When a process is paused, contents of all CPU registers (accumulators, index registers) are saved here.

Where is PCB stored? The OS stores PCBs in a Process Table (an array or linked list) in Kernel Memory.

5️⃣ Process Creation: fork()

How UNIX-based systems create new processes.

When fork() is called, the OS creates a Child Process that is an exact duplicate of the Parent Process (duplicate memory, PCB, open files).

int pid = fork();

// fork returns DIFFERENT values to each:
if (pid < 0) /* Error */
if (pid == 0) /* I am the CHILD */
if (pid > 0) /* I am the PARENT (pid = child's ID) */

🎓 GATE Math Shortcut: fork() Trees

If a program calls fork() n times sequentially in a loop:

  • Total processes created = 2ⁿ
  • Number of CHILD processes = 2ⁿ - 1
Example:
fork(); fork(); fork();
Total processes = 2³ = 8. (1 parent + 7 children).
exec(): Replaces process memory with a brand new program.
wait(): Parent pauses to wait for child to finish.
exit(): Terminates process, frees resources.

User vs Kernel Threads

User-Level Threads

  • Managed entirely by user-space library (e.g., POSIX pthreads).
  • OS kernel doesn't know about them.
  • Fast context switch (no mode switch).
  • Drawback: If one thread blocks on I/O, the kernel blocks the entire process (all threads halt).

Kernel-Level Threads

  • Managed by the OS natively (Windows, Linux).
  • Slower context switch (requires mode switch to Kernel mode).
  • Advantage: If one thread blocks, OS can schedule another thread from the same process. Multiprocessing is possible.

🧪 Practice Questions (GATE Focus)

▶ Q1: Consider a program with the following code snippet. How many child processes are created?
int main() {
  fork();
  fork();
  fork();
  return 0;
}
Answer: 7
Using the formula for `n` consecutive forks: Number of child processes = 2ⁿ - 1. Here n=3, so 2³ - 1 = 8 - 1 = 7 child processes. The total number of processes is 8.
▶ Q2: Which of the following state transitions is NOT valid?
  • A) Ready → Running
  • B) Running → Ready
  • C) Waiting → Running
  • D) Running → Waiting
Answer: C (Waiting → Running)
A process in the Waiting (Blocked) state must first return to the Ready state when its I/O completes. It must then wait for the CPU scheduler to pick it before it can move to Running.
▶ Q3: Which of the following components of program state are shared across threads in a multithreaded process?
  • I. Register values
  • II. Heap memory
  • III. Global variables
  • IV. Stack memory
Answer: II and III only
Threads within the same process share the Text (code), Data (global variables), and Heap memory. Each thread has its own private Stack and Registers (including the Program Counter) to keep track of its specific function calls and execution point.
