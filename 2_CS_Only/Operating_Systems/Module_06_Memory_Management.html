🧠 Module 6: Memory Management Basics

Logical vs Physical Addresses, Fragmentation, and the theory of Paging

📖 Core Fundamental Theory: The "Why"

Before jumping into formulas, we must understand the core problem the OS is trying to solve. In a modern computer, the CPU executes instructions. To execute an instruction, it must fetch it from the Main Memory (RAM). But we have a problem: multiple programs want to be in RAM at the same time (Multiprogramming).

Logical Address (Virtual)

This is the address generated by the CPU. The CPU is completely blind to the actual hardware RAM. It lives in a fantasy world where it thinks a program starts exactly at address 0.

Physical Address (Real)

This is the actual location in the silicon hardware (RAM). The program almost NEVER starts at address 0 in physical RAM because the OS kernel usually lives there.

The MMU (Memory Management Unit)

The MMU is a hardware chip that sits between the CPU and the RAM. It intercepts every single Logical Address the CPU creates and translates it into a Physical Address before sending it to the RAM. This translation happens at runtime.

2️⃣ The Problem: Fragmentation

Historically, OS designers allocated memory continuously (Contiguous Allocation). This led to a massive theoretical problem called Fragmentation, which comes in two flavors:

Internal Fragmentation

Concept: Memory is divided into fixed-sized blocks. A process is given a block, but the process is slightly smaller than the block. The leftover space inside the block is wasted.

Analogy: You buy a 1-liter water bottle, but only drink 800ml. The remaining 200ml is wasted inside your specific bottle.

External Fragmentation

Concept: There is enough TOTAL free memory in the RAM to satisfy a request, but it is scattered in small, non-contiguous holes. The OS must deny the request.

Analogy: 5 people want to sit together in a movie theater. There are 10 empty seats total, but they are scattered all over. The group cannot sit.

3️⃣ The Solution: Paging (Non-Contiguous)

To solve External Fragmentation entirely, computer scientists invented Paging. The core idea is simple: We break the program and the RAM into equally sized puzzle pieces.

  • Pages: The logical memory (the program) is divided into equal-sized blocks called Pages.
  • Frames: The physical memory (the RAM) is divided into blocks of the exact same size called Frames.
  • Rule: Page Size = Frame Size. ALWAYS.

⚠️ GATE TRAP: Does Paging suffer from Fragmentation?

Paging 100% eliminates External Fragmentation (because any page can go into any available frame). However, it DOES suffer from Internal Fragmentation. If a program's size isn't a perfect multiple of the page size, the very last page will have some wasted space!

4️⃣ How the MMU translates Addresses (The Math)

When the CPU generates a Logical Address, it is split into two parts:

Logical Address (Generated by CPU)

Page Number (p)
Offset (d)
➔ translated to ➔

Physical Address (Sent to RAM)

Frame Number (f)
Offset (d)

Notice that the Offset (d) stays exactly the same! The MMU's only job is to look up a table (called the Page Table) to find out which Frame Number (f) corresponds to the CPU's requested Page Number (p).
