Symmetric vs Asymmetric, RSA Algorithm Math, Diffie-Hellman, Digital Signatures & Firewalls

📖 Core Fundamental Theory: The 4 Security Pillars

1. Confidentiality (Encryption): Only the authorized sender and receiver should understand the contents of the transmitted message.
2. Integrity (Hashing / MAC): Ensures the message was not modified, deleted, or inserted while in transit.
3. Authentication: Both sender and receiver should be able to confirm the true identity of the other party.
4. Non-Repudiation (Digital Signatures): A sender cannot falsely deny having sent a message that they originated.

1️⃣ Symmetric vs Asymmetric Cryptography

Feature Symmetric Key Cryptography Asymmetric Key Cryptography
Number of Keys 1 Shared Secret Key (Used for both Enc & Dec) 2 Keys per entity (Public Key & Private Key)
Key Count for N users N(N - 1) / 2 Keys 2N Keys
Execution Speed Very Fast (used for bulk data encryption) Slow (computationally expensive modular math)
Key Algorithms DES, 3DES, AES RSA, Diffie-Hellman, ECC

2️⃣ The RSA Public Key Cryptosystem

Based on the mathematical difficulty of factoring the product of two extremely large prime numbers.

Key Generation Steps:

  1. Select two distinct prime numbers: p and q.
  2. Compute modulus: n = p × q
  3. Compute Euler's totient: φ(n) = (p - 1)(q - 1)
  4. Choose public key exponent e such that: 1 < e < φ(n) and gcd(e, φ(n)) = 1.
  5. Calculate private key exponent d such that:
    (d × e) ≡ 1 (mod φ(n))  →  d = (k × φ(n) + 1) / e
  6. Public Key: (e, n)  |  Private Key: (d, n)
Encryption: C = Me mod n
Decryption: M = Cd mod n

Step-by-Step Worked GATE Numerical:

Let p = 3, q = 11, e = 7. Plaintext message M = 2. Find private key d and Ciphertext C.

1. Modulus: n = 3 × 11 = 33

2. φ(n) = (3 - 1)(11 - 1) = 2 × 10 = 20

3. Finding d: (d × 7) mod 20 = 1 → Testing d = 1, 2, 3...
   For d = 3: (3 × 7) mod 20 = 21 mod 20 = 1! → d = 3.

4. Encryption: C = 27 mod 33 = 128 mod 33 = 29.

5. Verification Decryption: M = 293 mod 33 = 24389 mod 33 = 2 (Original recovered!).

3️⃣ Diffie-Hellman Key Exchange

Allows Alice and Bob to securely compute a shared symmetric secret key over an eavesdropped network without transmitting the secret itself.

1. Public numbers: Prime p and primitive root g.

2. Alice picks secret x → sends Bob: R1 = gx mod p.

3. Bob picks secret y → sends Alice: R2 = gy mod p.

4. Alice computes key: K = (R2)x mod p = (gy)x mod p = gxy mod p.

5. Bob computes key: K = (R1)y mod p = (gx)y mod p = gxy mod p.

Vulnerability: Man-in-the-Middle (MitM) Attack! Diffie-Hellman does not authenticate the parties. An attacker in the middle can negotiate two separate keys with Alice and Bob unless digital certificates are used.

4️⃣ Digital Signatures & Firewalls

Digital Signatures

Provides Authentication, Integrity, and Non-repudiation.

• Signing: Sender encrypts the hash of the message using the Sender's Private Key (Signature = Hash(M)d_sender mod n).

• Verification: Anyone can decrypt the signature using the Sender's Public Key (e_sender) and compare the hash!

Firewall Types

  • • Packet Filter (Stateless, L3/L4): Filters by Source/Dest IP, Port number, and TCP flags.
  • • Stateful Inspection (L4): Tracks full connection states (blocks incoming packets that don't match an established outbound connection).
  • • Application Gateway / Proxy (L7): Deep packet inspection for application payloads.

5️⃣ GATE Traps to Avoid

⚠️ TRAP 1: Modulus Selection: n vs φ(n)

In RSA:
• φ(n) is used ONLY to compute the private key d: (d × e) mod φ(n) = 1.
• n is used in the actual Encryption and Decryption formulas: C = Me mod n and M = Cd mod n!

⚠️ TRAP 2: Which Key is Used for What?

• For Confidentiality (Privacy): Encrypt with Receiver's Public Key. (Only the receiver can decrypt with their private key).
• For Authentication (Signature): Encrypt with Sender's Private Key. (Anyone can verify using sender's public key, proving it came from sender!).
